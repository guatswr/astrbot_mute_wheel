# QQ 群禁言大转盘

一个用于 AstrBot + OneBot v11（`aiocqhttp`）的 QQ 群娱乐插件。

## 玩法

1. 群友发送 `禁言大转盘`。
   - 若发送者是管理员或群主，插件不会启动转盘，而是随机发送一条可配置且不撤回的亚托莉风格拒绝文案。
2. 插件发送转盘 GIF，默认 3 秒后撤回。
3. 插件发送随机落点的定格图，默认 3 秒后撤回。
4. 插件公布禁言时长，并开始默认 10 秒倒计时。正常执行禁言时，这条结果文案不会撤回。
5. 倒计时结束前，抽取者可发送 `wssb`、`亚托利我错了` 或 `亚托莉我错了` 求饶。
6. 禁言生效后，其他群友可在救援窗口内发送 `nssb` 为抽取者解禁；倒计时阶段发送不会提前拦截禁言。
7. 求饶或救援成功后，插件发送亚托莉风格文案并保留成功口令和文案；约 3 秒后尽力撤回本轮此前的触发消息、图片和结果，避免刷屏。

同一个群同一时间只保留一轮。默认在禁言后的 5 分钟内接受 `nssb`；短于 5 分钟的禁言按实际时长保留。救援窗口可在 AstrBot WebUI 的插件配置中调整，设为 `0` 表示整个禁言期间都可救援。

## 安装与权限

将整个目录放入 AstrBot 的 `data/plugins/astrbot_plugin_mute_wheel`，或将仓库地址交给 AstrBot 插件安装器，然后在 WebUI 中重载插件。

必须满足以下条件：

- 使用 QQ OneBot v11 / `aiocqhttp` 适配器（例如 NapCat）。
- 机器人是目标 QQ 群的管理员或群主，否则无法禁言、解禁或撤回群友消息。
- 目标成员的群权限低于机器人；QQ群主通常不能被机器人禁言。

插件使用 OneBot 的数组消息段并以内联 Base64 发送图片，因此 AstrBot 与 QQ 协议端不在同一容器时也不依赖共享图片路径。

## 轮盘落点

GIF 已重新识别并拆为 `img/frames` 下的 18 张定格 PNG。文件名采用 `帧序号_实际秒数s.png`，代码会自动核对文件名秒数与禁言秒数：

| 帧 | 结果 | 实际秒数 |
|---:|---|---:|
| 00、09 | 2 小时 | 7200 |
| 01、11 | 10 分钟 | 600 |
| 02、12 | 3 天 | 259200 |
| 03、13 | 1 分钟 | 60 |
| 04、14 | 1 天 | 86400 |
| 05、15 | 半小时 | 1800 |
| 06、16 | 1 月 | 2592000 |
| 07、17 | 5 分钟 | 300 |
| 08 | 1 小时 | 3600 |
| 10 | 1 年 | 超过 QQ 上限，默认不参与抽取 |

插件只从不超过当前禁言上限的停帧中等权抽取，图片标注、结果文案与 OneBot 禁言秒数因此始终一致。QQ 单次禁言通常最多 30 天，所以默认有 17 个停帧参与抽取，“1年”格不会被抽中；调低配置上限时，更长的停帧也会自动排除。

原 GIF 的帧延时字段为 `0 ms`，不同客户端可能采用不同的默认速度。仓库中的 GIF 已重建为明确的 `30 ms/帧`，约为常见默认播放速度的三倍；可用 `scripts/rebuild_wheel_assets.py` 从当前映射重复生成 GIF 和全部停帧。

## 可配置项

- GIF、定格图和收尾文案的展示时长
- 公布结果后的禁言倒计时
- 禁言后的友情救援窗口
- 实际禁言时长上限（最低 1 分钟，只能调低，不能超过 30 天；超出上限的停帧不参与抽取）
- 管理员或群主尝试参与时的洗牌袋拒绝文案；同一群会轮完全部文案后再洗牌，支持 `{role}` 占位符
- 是否尝试撤回群友发送的转盘触发消息和无效口令；成功的求饶、救援口令始终保留

所有会话状态保存在内存中。AstrBot 重载或重启后，已经生效的 QQ 禁言仍由 QQ 保持，但旧轮次的 `nssb` 救援状态不会恢复。

## 代码结构与修改文案

- `main.py`：AstrBot 注册、群消息识别和事件路由。
- `wheel_service.py`：转盘、倒计时、求饶、救援和清理状态机。
- `wheel_models.py`：18 个落点、素材路径和会话数据结构。
- `onebot_gateway.py`：OneBot 发送、撤回、成员身份和禁言接口。
- `copywriting.py`：所有群内可见的默认文案及结果文案生成函数。

要长期修改角色语气，直接编辑 `copywriting.py`。其中按临时提示、权限拒绝、成功/失败和抽奖结果分区；无需接触状态机。管理员/群主拒绝文案也可以在 WebUI 中填写多条临时覆盖，配置留空时自动回退到该文件的默认文案。权限文案采用按群、按身份独立的洗牌袋：全部候选各出现一次后才会重新洗牌，并避免两轮交界处连续重复。
